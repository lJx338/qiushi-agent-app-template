# 应用权限规格

每个动作填写：使用角色、动作权限、本人/部门/指定数据范围、可读/可写字段、源连接模式、审批条件、模型/导出/外发用途、后台执行身份、撤权与产物处理。

安装授予应用能力上限，员工仍须获授权；各层检查同时成立才能执行。源连接区分企业共享与代表员工：共享应用身份不自动继承员工源权限，用户无权时不能改用机器人兜底。业务应用不维护另一套员工账号，不选择 tenant，不持有 token。SDK 开发身份只是合成数据。

申请人与审批人分离，审批绑定业务版本。子 Agent/跨应用调用不扩大委托范围；后台任务使用明确可撤销身份。读取不自动授予导出或送模型权限；输出、缓存、搜索、会话和文件都要考虑字段与撤权限制。

至少准备以下适用测试，分别标明开发模拟或真实集成；未实现的连接器场景保持未实现：

| 场景 | 预期 |
|---|---|
| 不同租户/不同员工访问他人对象 | 拒绝且不泄露对象信息 |
| 员工无权限、安装未授权或停用 | 均拒绝 |
| UI 隐藏后直接调用工具/API | 服务端规则仍生效 |
| 额外输入字段、隐藏成本、列表/搜索/附件 | 不越权读写，不向模型提供敏感原文 |
| 平台允许但外部身份无权 | 拒绝，不切换更高权限身份 |
| 缓存/历史结果/审批恢复前撤权 | 按当前身份重检，不返回旧授权内容 |
| 子 Agent、队列、定时与外发 | 有明确范围、用途和审计，不自动扩权 |
| 超时或取消时远端可能已写入 | 核对中，不误报撤销或无条件重发 |

当前 kit 仅模拟动作权限/租户客户查询及内存幂等，不实现上述完整生产权限。需要的新权限契约记录在 PRD，不在应用里自行补一套高权限连接。
